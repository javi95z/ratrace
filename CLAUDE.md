# The Rat Race

A life-sim about money. pnpm monorepo, Node ≥ 22 (`source ~/.nvm/nvm.sh && nvm use`).

## Layout

Dependencies only point down this list:

| Where | What |
|---|---|
| `packages/engine` | The rules: pure state machine (`createGame`, `applyRound`, quotes, score). `ENGINE_VERSION` in `src/version.ts`. |
| `packages/content` | Data the engine runs on: cards, cities, careers, items, badges, headlines, and the bots (`bots.ts`: the balance tool's players, and the rats the server seats in public games; they go into each rules bundle). `CONTENT_VERSION` in `src/content.ts`. |
| `packages/i18n` | The interface's words: `messages/{en,es,ru}.json`, `LOCALES`, `messagesFor`. |
| `packages/core` | The game's logic, no UI and no browser: `session/*` (local, memory, resilient, rooms, ranked, saves, profile, rank), `game/*` (round store, present, records, guide, rivals, avatar, rules registry…), `lib/format`, `lib/mask`. Import as `@ratrace/core/<dir>/<name>`. |
| `packages/online` | The client of the servers, on top of core: account (`supabase`, `types`, `offline`), cloud saves (`mirror`, `merge`, `follow`), ranked and rooms APIs, `connect` (the only file that names `@supabase/supabase-js`), error reports. Import as `@ratrace/online/<name>`. |
| `apps/web` | Next.js + next-intl. Screens, UI kit, `game/context.tsx` (the one place that wires session, store and cloud), browser-only pieces (`session/indexeddb`, `game/browserBasket`, `session/rulesFromSite`, `online/index` (browser wiring), `online/captcha` (Turnstile), `online/language` (locale in the URL)), `testing/*` (ranked and room servers for tests, built on the real edge-function code). |
| `apps/mobile` | The Expo app (React Native, Hermes), on branch `expo` until phase 5 (`docs/superpowers/specs/2026-10-20-expo-app-design.md`). Mirrors `apps/web/src`: `game/screens/*` (each web screen's name, exports and props), `game/context.tsx` (wires the session, the round store, the phone's store and the cloud, with the web's hooks; signing out starts the provider again over the same cloud; `game/events.ts` the web's counting, held to it, sent by `online/track.ts` to the project's `track` function in a release build only, the install once), `kvStore.ts` (the phone's store, on `expo-sqlite/kv-store`, one key per finished life), `rules/` and `game/olderRules.ts` (the older rules a life in progress finishes under; the `v*.js` are copied by `pnpm rules` from `apps/web/public/rules`, not committed), `online/` (the twin of the web's `online/index.ts`: `phoneOnline`, offline with no `EXPO_PUBLIC_SUPABASE_*`; the session in `kvStore.ts` under `ratrace:session:`, renewed only while the app is in front; `page.ts` AppState and expo-network, and `phoneConnection` for `useRanking`; `held.ts` the account's lives in progress handed to the mirror only once the game's first screen is drawn (`firstScreenDoor`, opened by `game/context.tsx`, a 5 s backstop; the finished lives and the lives in progress asked at once, the rest of the reading after the held answer), played back a life at a time (the mirror's `pace`: the copies it takes first, the offers after); Continue uses the newest copy the account knows of, waiting up to 1.5 s for it while the account signs in or is read for that life at a start (`untilFresh` in `game/context.tsx`); `language.ts` an account's language followed through `setLocale`; `errors.ts` ErrorUtils and Hermes' rejection tracker, places as `app:<path>`; `browser.ts` opens Google's auth session back to `theratrace://auth` (a second trip waits for the first to end); only that trip's code is exchanged, against its flow (`@ratrace/online/connect`); `app/auth.tsx`, that address handed to the router by Android, only goes back or home; `captcha.tsx` Turnstile for the guest sign-in when `EXPO_PUBLIC_TURNSTILE_SITE_KEY` is set, in a WebView given the site's address, out of sight unless it has something to ask, then in a sheet; `track.ts` the events; `push.ts` the game's notices through Expo's push service when `EXPO_PUBLIC_EAS_PROJECT_ID` (or app.json's `extra.eas.projectId`) is set on a real phone, outside Expo Go (no switch otherwise, and the library never loaded): asked once (a refusal and the token the account has noted in `kvStore.ts`), the token kept with the account (`claim_push_token`) once a start and again for a new token, account or language, off only once the account forgot it, taken from an account before it is signed out of, and a tap opening only the app's own screens (`theratrace://<page>`, `pageOf`) once every open sheet is closed as the player would close it (`closeAllSheets` in `ui/back.ts`), never with one left open over it), `ui/` (the pixel kit on Skia and Reanimated), `app/` (expo-router routes: the pages under `[locale]/` as the Next web's (`/es/room?code=`, `/en/rankings#friends`; any other language the router's page of nothing), `/` leading to one, the phone's links (`theratrace://<page>`) made pages of the phone's language by `+native-intent.tsx`, every move between pages through `game/pages.ts` (`hrefOf`, `useGo`; the architecture test holds it); on the web the language is the address's (`game/useLanguage.web.ts`); `/scene`, `/kit`, `/dev` development only, `/perf` the probe's build only, `auth` Google's way back), `scripts/` (shots, sprites, rules, the timing collector, `webSize.ts`, `web-life.ts`), `testing/` (scenes, stand-ins). Parity with the web is shot scene by scene: `docs/superpowers/reports/2026-10-21-phase-2-parity.md` (phase 1's beside it). The app's own web (phase 5: `npx expo export --platform web`, to take the Next web's place) is the same app: what differs in a browser is a `.web.ts(x)` twin of the phone's file with the same exports, which Metro picks for the web and the vitest project `phone-web` tests (`*.web.test.*`; after making a twin, `rm -rf node_modules/.vitest-cache`): the store on the Next web's IndexedDB and localStorage keys (`kvStore.web.ts`), older rules fetched from `/rules` (`game/olderRules.web.ts`), sprites, glows, charts and drawings as images, CSS and SVG (no Skia), the share card on a canvas, the cloud wired as the Next web wires it (`online/index.web.ts`: no `storage`, Google by redirect), the page's text laid out as Chrome lays out the Next web's (`ui/strut.web.ts`, `ui/systemFace.web.ts`, `ui/emojiHeight.web.ts`, `ui/layoutTop.web.ts`), the Next web's words where the phone has its own (`game/ownWords.web.ts`), the game's notices the browser's own push subscription as the Next web takes it (`online/push.web.ts`: VAPID web push into `push_subscriptions`, offered only with `EXPO_PUBLIC_VAPID_PUBLIC_KEY`, the Next web's `NEXT_PUBLIC_VAPID_PUBLIC_KEY`, and a browser with a worker, a push manager and notices; the worker's `push` and `notificationclick` are the Next web's, word for word). It offers to install itself as the Next web does (`pwa/install.web.tsx`: Chrome's install prompt, kept if it comes before the game is drawn, the iOS and browser steps in a Sheet, Home's offer from the second visit until a no, `ratrace.installOffer` in `kvStore.web.ts`, `app_installed` counted through `useTrack()`, the iOS standalone viewport fix; nothing on the phone). It counts visits and the eight events with Vercel Web Analytics as the Next web does (`pwa/visits.web.tsx`: `@vercel/analytics/react` mounted by `app/_layout.tsx`, the address without its query, production only; the events also through Vercel's `track` beside the game's own, `alsoToVercel` in `game/context.tsx`; nothing on the phone), and writes the language cookie again for every page opened (`game/useLanguage.web.ts`). On a wide screen it lays out as the Next web does (`ui/desk.web.ts`: `useIsDesk` from 64rem, `useIsWide` from 40rem, false in the export's HTML; the phone has neither): a life in three columns (`game/screens/PlayDesk.web.tsx`, the phone's twin nothing), the skip links to the round and its actions at every width (`game/screens/SkipLinks.web.tsx`), a sheet in the middle as a dialog that takes the focus (`ui/sheetDialog.web.tsx`: the Modal's dialog named by the title, the panel focused or what the sheet names, Tab kept round it, a backdrop that takes no focus, the page behind inert), the end of a life in two columns, the rankings, records, collection and legal page in the web's `max-w-2xl` column (`WIDE_COLUMN`); it is played with the keyboard as `docs/keyboard.md` says (`ui/keyboard.web.tsx`, its reference and the settings' guide in `game/KeyboardHelp.tsx`: shortcuts heard before the control in focus, never from a field or a sheet; composite controls found by their `dataSet` marks), and the browser's Back closes an open sheet (`ui/sheetHistory.web.ts`, the Next web's `closeOnBack`, used by `ui/back.ts`). The export is static (`web.output: "static"`): each page in each language its own HTML (`en/index.html`, `es/play.html`), drawn on the build's machine as a first visit shows it (no window there: what reads the browser waits for it, every `useSyncExternalStore` has its server snapshot; Rules that guard this:
- `packages/core` and `packages/online` compile without DOM; eslint forbids `react`, `next`, `next-intl`, `@/*` and `window`/`localStorage`/`indexedDB` in them, and anything online or Supabase in core. A browser need goes in the web, behind a type the package exports.
- `apps/web/src/architecture.test.ts`: screens reach the game only through `GameSession`, never the engine's moves, the device or the cloud. It reads web, core and online as one tree (`@ratrace/core/x` = `@/x`, `@ratrace/online/x` = `@/online/x`).
- `apps/mobile/src/architecture.test.ts`: the same wall on the phone (no engine moves, device store or cloud in a screen; `@ratrace/online` beyond its types only in `online/*` and `game/context.tsx`; the device's storage named only in `kvStore.ts`, `game/context.tsx` and `testing/setup.ts`, the account's session among it; no `hitSlop`; nothing sent but through the Supabase client (`@ratrace/online/connect`), a development scene's "ready" to the shots' driver and the probe's lines to its collector, both on this machine; no `@/ui/sound`; a web page (react-native-webview) only in `online/captcha.tsx`; the phone's notices (expo-notifications) only in `online/push.ts`; nothing the app runs imports from `scripts/`, and nothing under `src` names the fake project's address or key), read with core as one tree.
- `apps/mobile/src/ui/devRoutes.test.ts`: test and development code (`testing/*`, `ui/kitMotion`) is named only by `/scene`, `/dev`, `/kit` and `/perf`, each `require`d behind `__DEV__` (`/perf`: `EXPO_PUBLIC_PERF`), so a release bundle holds none of it.
- Every i18n key must be used somewhere in web, core or apps/mobile; `phone.*` keys only by the app, never the web (both in `apps/web/src/i18n/messages.test.ts`). Russian addresses the player gender-neutrally.

Visits and where they come from: Vercel Web Analytics (no cookies), in the Vercel project's Analytics tab. Custom events (lives begun and ended by mode, challenge attempts, games with others begun and joined, accounts kept, installs, shares) are typed in `apps/web/src/pwa/events.ts`: never an id, a name or a score, production only; screens count through `useTrack()`. The same eight can be counted in the game's own project through the function `track` (`_shared/events.ts`; `private.app_events`, by day and platform, nothing of who sent them; any caller with the publishable key, and a ceiling of 20,000 a day for each event and platform), and `pnpm online:stats` prints them.

## Versions and games in progress

A life started under older rules keeps them until it ends: never interrupt a game.
- Bump `ENGINE_VERSION`/`CONTENT_VERSION` when rules or content change what a life does.
- `pnpm online:bundle` writes the bundle for the current versions and mirrors the older ones to `apps/web/public/rules`; `shipped.json` locks bundles already deployed.
- A new order (action) is listed in `ORDERS_SINCE` in `packages/core/src/game/rules.ts` (a test checks it against the bundles), so an older life never offers it.
- The app carries the older bundles too (`pnpm rules` copies `apps/web/public/rules` into `apps/mobile/src/rules`): a life under a version the app lacks waits for an update that carries it, never lost.

## Shipping

Work on `dev` and push `dev`. `main` is production: touch it only when asked.
The app (`apps/mobile`) is the exception until phase 5: work and push on `expo` (worktree `.worktrees/expo`), `git fetch && git rebase origin/dev` regularly, never merge it into `dev` or change the web for it unless asked.
Another session shares this repo and the Supabase project: `git fetch && git rebase origin/dev` before pushing or deploying.
Deploy order, only when asked: migration (`supabase db push --linked`) → `pnpm online:deploy` → `pnpm -s online:live-check` → `git push origin dev:main` (fast-forward) or a merge.
Never run `online:deploy`, `online:live-check`, `online:test-db` or `supabase config push` unasked. The local dev browser is a guest on the live Supabase: don't test saves by editing IndexedDB.

## UI conventions

Simplest UI that works; hide what can't be used. Details open in a dimmed modal `Sheet`, never inline. No framed box inside another. Spanish says "partidas", not "salas".
